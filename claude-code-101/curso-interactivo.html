¿Qué es Claude Code?

Una herramienta de codificación agéntica: entiende tu base de código, edita tus ficheros, ejecuta comandos y se integra con tus herramientas.

Qué lo separa de Claude.ai

Claude Code tiene acceso directo a tus ficheros, tu terminal y toda tu base de código. En vez de copiar y pegar código de un lado a otro, entra y hace el trabajo.

El diferenciador clave es que Claude Code funciona como un AI Agent.
⚠ Pregunta 1 del quiz oficial

Un agente de IA es software que interactúa con su entorno y ejecuta acciones para completar un objetivo definido, con un modelo de lenguaje operando en bucle en tiempo real. Los distractores que te ofrecen — un chatbot que responde en tiempo real, un editor con autocompletado, un servicio en la nube que aloja proyectos — describen herramientas que no actúan.

Qué puede hacer en la práctica

CapacidadEjemplo
Leer y entender tu base de códigoExplicar una funcionalidad o rastrear un bug por todo el código
Editar ficheros de todo el proyectoRefactorizar una función y actualizar todos los ficheros que la referencian
Ejecutar comandos de terminalBuild, tests, instalar paquetes — y usar la salida para decidir qué hace después
Buscar en la webDocumentación o referencias de API actualizadas

Los tres conceptos que hay que tener presentes

La ventana de contexto

Su memoria de trabajo. Cabe mucho, pero no todo a la vez. Por eso Claude busca formas estratégicas de encontrar respuestas sin cargar el repositorio entero.

Pide permiso

Por defecto pregunta antes de ejecutar comandos o hacer cambios. Tú mandas siempre.

⚠ Puede equivocarse

Puede malinterpretar tu intención, introducir un bug o sobre-diseñar una solución. Estar en el bucle es lo que te permite pillarlo pronto.

Cómo funciona Claude Code

Un bucle agéntico, una ventana de contexto gestionada, tools y permisos configurables — dentro de tu terminal.

El bucle agéntico

Escribes un prompt en Claude Code.

Reúne el contexto que necesita interactuando con el modelo, que devuelve texto o una llamada a una tool ejecutable.

Actúa — edita un fichero, ejecuta un comando.

Verifica si los resultados logran lo que pedía tu prompt.

Si sí, termina y espera. Si no, vuelve al bucle hasta que el resultado esté completo y sea verificable.

✓ Estás dentro del bucle

Durante todo el proceso puedes añadir contexto, interrumpir o redirigir al modelo.

Contexto

La ventana de contexto determina cuánto puede almacenar y referenciar: conversación, contenido de ficheros, salida de comandos. Al llegar al límite, Claude Code compacta la conversación: decide automáticamente qué eliminar o resumir.

⚠ Pregunta 2 del quiz oficial

Al llenarse el contexto no cambia a un modelo más pequeño, no borra tus ficheros más antiguos y no deja de funcionar. Compacta automáticamente la conversación para liberar espacio.

Tools

Las tools son la columna vertebral de los agentes. La mayoría de asistentes toman texto y devuelven texto; las tools le permiten a Claude decidir cuándo ejecutar código. Usa comprensión semántica para saber cuándo llamarlas y cómo usar su salida.

Los tres modos de permisos
⚠ Cuidado al saltarte los permisos

Barra libre para ejecutar comandos significa que un error puede ser más difícil de pillar antes de que ocurra.

Instalar Claude Code

Cinco sitios donde vive, y una regla para elegir: las novedades llegan primero al terminal.

Terminal

En macOS, Linux o WSL: curl de una vez, o brew install. En Windows: Invoke-RestMethod en PowerShell, curl en CMD, o winget.

⚠ El detalle que se olvida

Homebrew y winget no soportan auto-actualizaciones. El script de curl sí.

Tras instalar, ejecuta claude — si no responde, reinicia el terminal. Pasarás por el tema de color y el inicio de sesión (cuenta Pro, Max o Enterprise, o API key). Si tu organización tiene Enterprise, selecciona esa opción.

claude
◈ El alcance lo marca el directorio

Donde ejecutes claude, tendrá acceso a ese directorio y a todas sus subcarpetas.

Tu primer prompt

Le hablas como a cualquier asistente. Lo que cambia es cuánto le dejas hacer sin preguntar.

Auto-accept vs. approval

Pulsa Shift + Tab para ciclar entre modos.

ModoFicherosComandos
Approval modePide permiso cada vezPide permiso cada vez
Auto-accept modeSe aprueban automáticamenteSiguen requiriendo tu permiso
⚠ Detalle que se cuela

Auto-accept no es barra libre. Los comandos siguen pasando por ti.

Plan Mode

Dentro del mismo menú de Shift + Tab. Toma tu prompt y usa tools de solo lectura para analizar el código e investigar la implementación, hace preguntas aclaratorias y devuelve un plan detallado que puede ejecutar.

Brilla en
  • Cambios complejos
  • Revisión de código segura
  • Implementaciones multi-paso hacia una funcionalidad
No puede
  • Editar ficheros — solo lee
  • Ejecutar el plan sin que lo apruebes

Ejemplo: un toggle de modo oscuro

My app needs a dark mode implemented across the entire app. Can you
create a toggle switch on the header that allows a user to toggle
between light mode and dark mode? I need you to find a good contrast
color that works based on my existing light theme.

Deja que lo planifique, revisa el plan y, si te vale, acéptalo. Al final ves qué hizo y cómo llegó a sus conclusiones.

◈ Conclusión

Sé todo lo descriptivo que puedas. Usa Plan Mode para que Claude escarbe en los detalles antes de ejecutar nada.

El flujo explore → plan → code → commit

Sin él, la mayoría salta directamente a pedir código — y eso significa más correcciones de rumbo después.

Las cuatro fases

El prompt de ejemplo

I need to add WebP conversion to our image upload pipeline. Figure out
where in the pipeline it should happen, whether we need new dependencies,
and how to approach it.

Claude lee los ficheros relevantes, hace búsquedas web y te da un plan. Revísalo; si no encaja, pídele que revise áreas concretas.

◈ Por qué Plan Mode importa tanto

Es el mejor sitio para corregir el rumbo, porque es antes de que se escriba ningún código.

También puedes ejecutar el subagente de explore sin estar en plan mode si solo quieres un resumen general del repositorio sin intención de cambiar nada.

✓ Truco rápido

Si Claude tropieza una y otra vez con lo mismo, pídele que guarde la solución en su fichero CLAUDE.md.

⚠ Pregunta 3 del quiz oficial

El flujo es Explore → Plan → Code → Commit. Los distractores suenan igual de plausibles: Code → Test → Deploy → Monitor, Write → Review → Merge → Ship, Prompt → Accept → Push → Repeat.

Gestión del contexto

El contexto es la memoria de trabajo de Claude. Cada fichero leído, cada comando ejecutado, cada mensaje — todo ocupa espacio.

Qué pasa cuando se llena

Se compacta automáticamente: resume los detalles importantes y elimina resultados de tools innecesarios.

⚠ La compactación no es gratis

El proceso puede perder detalles.

Los tres comandos

ComandoQué hace
/compactCompacta todo lo anterior. Libera espacio conservando memoria de lo trabajado
/clearEmpieza de cero sin memoria. Lo elimina todo
/contextTamaño de tu contexto, qué categorías ocupan más y un gráfico del desglose
¿/compact o /clear?

¿Lo que viene ahora tiene que ver con lo que acabas de hacer?

Tres formas de gastar menos

⚠ Lo contraintuitivo del capítulo

Un prompt vago no ahorra contexto: lo gasta. Sin instrucciones claras, Claude explora más código y razona más por su cuenta — y eso ocupa mucho más que un prompt detallado.

Coste en contexto, según el curso

Barras cualitativas: el curso no da cifras salvo el umbral del 10 % de tool search. La idea que sí da es el orden: un servidor MCP inactivo cuesta más que su equivalente en CLI o que una skill.

  • Gestiona tus servidores MCP. Cargan todas sus tools en contexto por defecto, aunque no las uses. Las Skills no lo cargan todo de entrada.
  • Usa subagentes. Contexto completamente separado: hacen el trabajo y devuelven solo un resumen. Para «¿dónde están los endpoints de autenticación?», es la herramienta.

Revisión de código

Tres funcionalidades pequeñas que quitan mucha fricción del flujo de git.

Revisar con un subagente

Antes de subir un PR, que un subagente revise tus cambios: corre en su propia ventana de contexto con ojos frescos y no arrastra el sesgo del agente que acaba de escribir ese código.

Restríngelo a solo lectura

Un revisor debe señalar problemas, no editar ficheros.

Versiónalo

Mete la configuración del subagente en el repositorio para que todo el equipo use el mismo revisor.

La skill /commit-push-pr

Commit, push y creación del PR en un solo paso. Si tienes un servidor MCP de Slack con los canales listados en tu CLAUDE.md, publica el enlace del PR en el canal del equipo automáticamente.

Retomar con --from-pr

Cuando Claude crea un PR con gh pr create, la sesión queda enlazada a ese PR. Para volver a ella:

claude --from-pr <PR_NUMBER>

El fichero CLAUDE.md

Memoria persistente del proyecto. Un script de onboarding para tu base de código.

El problema que resuelve

Sin él, Claude empieza de cero cada vez: reexplora el código, averigua dependencias, entiende qué hay implementado — y a veces hace suposiciones.

⚠ Pregunta 4 del quiz oficial

Claude Code lo lee automáticamente al inicio de cada sesión, y su contenido se añade a tu prompt. No solo tras ejecutar /init, no una vez al crear el proyecto, no solo cuando lo pides. /init sirve para generarlo, no para que se lea.

Un ejemplo

# Project

This is a Next.js 15 app using the App Router, Tailwind, and Drizzle ORM.

# Commands
- Dev server: `pnpm dev`
- Run tests: `pnpm test`
- Lint: `pnpm lint`

# Code Style
- Use 2-space indentation
- Prefer named exports
- All API routes go in app/api/
- Use server actions instead of API routes where possible

ProyectoDirectorio raíz del proyectoCompartido con el equipo (versiónalo)
UsuarioTu carpeta de configuraciónSolo para ti, en todos tus proyectos

Trucos

  • Guarda las correcciones en memoria. Si te ves corrigiendo lo mismo, pídele explícitamente que lo guarde.
  • Referencia documentación con @:
## README.md

Please read if you need more info: @README.md

Arranca sin él para ver dónde tienes que corregir el rumbo constantemente. Así el fichero queda compacto y centrado en lo necesario. Cuando estés listo, /init te genera uno.

Subagentes

Delegar tareas a agentes con su propia ventana de contexto aislada, que devuelven solo el resumen.

Cómo funciona

Agente principal

«Explórame esta base de código»

→lanza subagente
Subagente

Corre en paralelo, con contexto propio. Explora, lee, busca.

Subagente

Termina y resume sus hallazgos

→devuelve resumen
Agente principal

Recibe solo la respuesta, no el viaje

◈ El resultado

Obtienes la respuesta que buscabas sin que todo el viaje que hizo falta para llegar a ella ensucie tu contexto principal.

Crear el tuyo

Se definen en ficheros Markdown con frontmatter YAML. Lo fácil es que te lo genere Claude:

/agents

→ «Create new agent». Eliges alcance, propósito, tools y hasta color. Claude genera nombre, descripción y prompt — y eso también le dice cuándo llamarlo.

Personalización adicional

Memoria persistente

El subagente retiene memoria entre conversaciones. Útil si lo usas siempre en los mismos proyectos.

Precargar skills

Con la clave skill, listándolas por nombre. Ojo: aquí la skill entera se carga en contexto, al revés que en la conversación principal.

MCP

Un estándar abierto para conectar Claude Code a herramientas y datos externos. Buena parte de tu contexto vive fuera de tu base de código.

Añadir un servidor

claude mcp add
TipoPara qué
HTTP serversServicios remotos alojados por el proveedor, por red
Stdio serversProcesos locales en tu máquina

Dentro de una sesión, /mcp te deja ver qué está conectado, comprobar el estado y desactivar lo que no necesites.

Los tres alcances

Solo en el proyecto actual, solo para ti. El alcance más estrecho: nada se comparte y nada te sigue a otros repositorios.

Disponible en todos tus proyectos. Tuyo, pero global — el sitio de los servidores que usas siempre, independientemente del repositorio.

Un fichero .mcp.json versionado en el repositorio. Cualquiera que trabaje en el código obtiene exactamente los mismos servidores automáticamente.

El coste en contexto

Los servidores MCP añaden definiciones de tools a tu contexto aunque no las uses. Tres alternativas más baratas:

En vez de…Usa…Por qué
Un servidor MCP de GitHub o AWSLa CLI (gh, aws)No añade definiciones de tools persistentes
Un servidor MCP para un procedimientoUna SkillSolo nombre y descripción en contexto; el resto bajo demanda
Dejarlo todo conectado/mcp y desactivarLo que no usas, no debería costarte
⚠ El número que hay que recordar

Si tus tools de MCP superan el 10 % de tu ventana de contexto, Claude Code cambia automáticamente a tool search mode, que descubre las tools bajo demanda — aunque puede no funcionar de forma tan fiable.

Hooks

Comandos en puntos concretos del ciclo de vida. La diferencia con todo lo demás del curso: los hooks son deterministas. Siempre se ejecutan.

Puedes decirle en tu CLAUDE.md que ejecute Prettier tras cada edición. La mayoría de las veces lo hará. Pero a veces no. Un hook lo hace todas y cada una de las veces.

Los cinco eventos

EventoCuándo se dispara
PreToolUseAntes de una llamada a una tool — puede bloquearla
PostToolUseDespués de que la llamada se complete
UserPromptSubmitAl enviar un prompt, antes de que Claude lo procese
StopCuando Claude termina de responder
NotificationCuando Claude envía una notificación
Constructor de hooks — settings.json

Bloquear con PreToolUse

El hook recibe el nombre de la tool y su entrada como JSON por stdin. El código de salida manda:

CódigoComportamiento
0Continúa normalmente
2Bloquea la acción. El mensaje de stderr se le devuelve a Claude como feedback, para que sepa por qué y pueda ajustarse
otroError no bloqueante: se te muestra, no detiene nada
⚠ El detalle que se olvida

El código de bloqueo es el 2, no el 1. Y el mensaje útil va a stderr, porque es lo que Claude lee.

Así se imponen reglas duras: bloquear escrituras en producción, bloquear rm -rf, bloquear commits a main. Lo que tu equipo necesite que esté garantizado, no sugerido.

Compartirlos con tu equipo

Los hooks en .claude/settings.json son de nivel proyecto y se versionan. Usa CLAUDE_PROJECT_DIR para referenciar scripts del proyecto, independientemente del directorio de trabajo actual de Claude.

◈ La frase del capítulo

Si algo tiene que pasar siempre y sin fallo, no lo pongas en un prompt. Ponlo en un hook.
