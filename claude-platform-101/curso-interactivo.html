¿Qué es la Claude Platform?

La infraestructura de Anthropic para construir con Claude programáticamente: envías peticiones estructuradas desde tu código y controlas cada detalle.

De qué se compone

  • Una API REST que puedes llamar desde cualquier lenguaje
  • SDKs para distintos lenguajes
  • Interfaces de línea de comandos
  • Una consola donde gestionas API keys, monitorizas uso, despliegas agentes gestionados y pruebas prompts

Un ejemplo real: redactar respuestas de un help desk

Te piden redactar la respuesta a un ticket siguiendo el tono del equipo, conectada a un botón de la interfaz. Caso perfecto para la Messages API:

client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-haiku-4-5",   # Haiku: buen encaje para una redacción sencilla
    max_tokens=1024,
    system=TONE_AND_GUIDELINES,
    messages=[
        {"role": "user", "content": ticket_content}
    ],
)

draft = response.content
ParámetroQué hace
modelQué modelo atiende la petición — aquí Haiku, porque la tarea es sencilla
max_tokensLimita la longitud de la respuesta
systemEl rol que juega Claude: aquí, el tono y las directrices
messagesArray de objetos; el rol user lleva el contenido del ticket
◈ La idea central

No estás construyendo un chatbot desde cero. Estás metiendo a Claude dentro de un producto que ya existe. De preguntarle a Claude a Claude es parte de mi producto.

Tu primera llamada a la API

Una messages.create con modelo, límite de tokens y mensajes. Todo lo demás del curso se construye encima.

Preparación

API key desde platform.claude.com (necesitas comprar créditos). Guárdala en .env.local.

⚠ Por qué en un fichero de entorno

Hardcodear keys en ficheros de código es exactamente cómo acaban filtradas en GitHub.

npm install @anthropic-ai/sdk
Constructor de la petición
⚠ Pregunta 1 del quiz oficial

Los tres parámetros que pide la llamada en sí son model, max tokens y messages. El system prompt es opcional y la API key no es un parámetro: vive en el cliente y en tu .env.local.

El detalle que cambia cómo lees la respuesta

El content de la respuesta es un array de bloques, no una cadena. Para texto normal suele haber uno de tipo text, pero Claude puede devolver varios — texto, llamadas a tools, thinking. Por eso siempre iteras y compruebas el tipo:

for (const block of response.content) {
  if (block.type === "text") {
    console.log(block.text);
  }
}

Elegir el modelo adecuado

Si vas por defecto al más listo, la factura te sorprenderá. Si eliges el más barato, la salida puede no dar la talla.

ℹ Nota del propio curso

En el momento de grabarlo, Claude Fable no estaba disponible de forma general y no aparece en el vídeo.

TierPerfilPara qué
Claude FableEl más capaz; por encima de Opus, con coste significativamente mayorTus desafíos más duros, cuando esa capacidad extra compensa
Claude OpusEl más capaz de las tres familias principales; el más lento y caro de las tresRazonamiento profundo, análisis complejo, codificación multi-paso, escritura con matices
Claude SonnetEl punto dulce: inteligencia, velocidad y coste equilibradosLa mayor parte del trabajo de producción
Claude HaikuEl más rápido y baratoAlto volumen y baja complejidad: clasificación, extracción, enrutado
¿Qué modelo para esta tarea?

Haiku. Alto volumen, baja complejidad. En el dashboard de operaciones del curso, cada fichero entrante se clasifica con Haiku.

Sonnet. El punto dulce para trabajo de producción con algo de matiz. En el ejemplo del curso, las actualizaciones a cliente se redactan con Sonnet.

Opus. Es el único caso del ejemplo que recurre a Opus. Una cola, tres modelos, elegidos por tarea.

Haiku, y sobra. Opus tarda más y lee más pulido — pero para dos frases ese pulido se desperdicia. Haiku responde a menudo en menos de un segundo.

La evaluación mínima

Reúne 20 o 30 ejemplos representativos de tu carga real. No hace falta nada sofisticado.

Pásalos por Haiku. Si la calidad aguanta, has terminado — y te has ahorrado mucho dinero.

Si no, sube a Sonnet. Y solo recurre a Opus cuando la tarea lo pida.

models = ["claude-haiku-4-5", "claude-sonnet-4-6", "claude-opus-4-7"]

for model in models:
    response = client.messages.create(
        model=model,
        max_tokens=300,
        messages=[{"role": "user", "content": prompt}],
    )
    print(model, response.usage)

response.usage te da los tokens de entrada y salida directamente de la API, que es sobre lo que se calcula tu factura.

◈ La regla

El modelo correcto es el más barato cuya salida publicarías de verdad.

El bucle del agente

Una sola llamada devuelve una sola respuesta. Un agente es Claude ejecutando los dos lados del bucle sin un humano en medio.

El bucle, turno a turno

El script completo

tools = [
    {
        "name": "get_weather",
        "description": "Get the current weather for a city.",
        "input_schema": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "The city to get weather for"}
            },
            "required": ["city"],
        },
    }
]

messages = [{"role": "user", "content": "What should I wear in Austin today?"}]

while True:
    response = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=1024,
        tools=tools,
        messages=messages,
    )

    if response.stop_reason == "end_turn":
        for block in response.content:
            if block.type == "text":
                print(block.text)
        break

    if response.stop_reason == "tool_use":
        tool_results = []
        for block in response.content:
            if block.type == "tool_use":
                result = run_tool(block.name, block.input)
                tool_results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": result,
                })
        messages.append({"role": "assistant", "content": response.content})
        messages.append({"role": "user", "content": tool_results})
◈ La frase del capítulo

Tú eres dueño del bucle y de las tools. Claude es dueño del razonamiento.

Al ejecutarlo verás dos turnos: uno con stop_reason: tool_use (Claude pide el tiempo de Austin) y otro con end_turn (te dice que te pongas algo ligero). Dos llamadas a la API, una ejecución de tool, una respuesta final.

¿Qué es el uso de tools?

Una tool es una función que tú defines y expones. Claude decide cuándo llamarla.

⚠ Pregunta 2 del quiz oficial

Claude no ejecuta la tool — tu código sí. Claude pide la llamada, tu código ejecuta la función, el resultado vuelve a Claude. (La excepción son las server tools del capítulo 07, que ejecuta Anthropic.)

Las tres partes de una definición

{
  "name": "lookup_building_code",
  "description": "Look up a specific building code section by its identifier. Returns the full text of that code section.",
  "input_schema": {
    "type": "object",
    "properties": {
      "section": {
        "type": "string",
        "description": "The building code section to look up"
      }
    },
    "required": ["section"]
  }
}
⚠ La causa número uno de fallos

La description es lo que Claude lee para decidir si llamar a la tool. Si escribes una descripción vaga, obtienes mal uso de tools. Es la razón número uno de que los agentes fallen o no cojan las tools disponibles.

Varias tools: despachar por nombre

function runTool(name, input) {
  switch (name) {
    case "get_weather":
      return getWeather(input.city);
    case "get_forecast":
      return getForecast(input.city);
  }
}

¿Una tercera tool? La añades al array, añades un case, y ya. Y fíjate en cómo elige Claude: lee las descripciones y mapea tu prompt a la tool correcta.

El tool runner

A mano escribes…
  • Un bucle while
  • Un switch de stop_reason
  • Meter resultados en messages
  • JSON schemas de cada función
El tool runner te da…
  • El bucle entero, interno
  • Los schemas, desde tus funciones reales
  • runner.untilDone() con el mensaje final
  • SDK de TypeScript, Python y Ruby
const runner = client.beta.messages.toolRunner({
  model: "claude-sonnet-4-6",
  max_tokens: 1024,
  messages: [{ role: "user", content: "I'm packing for a three-day trip to Denver…" }],
  tools: [getWeather, getForecast],
});

const finalMessage = await runner.untilDone();
◈ El espectro de delegación

Tú ejecutas, o delegas el bucle. En el extremo, los managed agents delegan el agente entero en Anthropic.

¿Qué es el thinking?

Claude razona paso a paso antes de responder, generando tokens de razonamiento — la chain of thought. Y el razonamiento no está oculto: lo ves en la respuesta.

Adaptativo en Opus 4.7

No eliges presupuesto de tokens. Lo activas y Claude decide dinámicamente cuándo pensar y cuánto.

⚠ La trampa que avisa el propio curso

El parámetro effort va dentro de output_config, no al lado del bloque thinking.

response = client.messages.create(
    model="claude-opus-4-7",
    max_tokens=16000,
    thinking={"type": "adaptive"},
    output_config={"effort": "high"},  # low | medium | high | xhigh | max
    tools=[weather_tool],
    messages=[{"role": "user", "content": "Plan a road trip out of San Francisco with two stops, weighing weather and drive time."}],
)

Los niveles son low, medium, high — el valor por defecto —, xhigh y max.

Cuándo sí y cuándo no

Ayuda con
  • Matemáticas y lógica multi-paso
  • Depuración de código
  • Análisis regulatorio
  • Compensaciones y comparación de opciones
Sáltatelo en
  • Clasificación simple
  • Extracción
  • Boilerplate
  • Ahí solo añade latencia y coste
ℹ Qué cambia en producción

Es la diferencia entre un agente que encuentra problemas de uno en uno y uno que los conecta: razonar a través de las secciones de un informe permite pillar que la carga de viento de la sección tres contradice la especificación de material de otra parte.

Tools integradas

Algunas capacidades son tan comunes que Anthropic las trae ya hechas. No escribes el código, no alojas el sandbox: declaras la tool y Anthropic la ejecuta.

Server tools vs. client tools

Corren en la infraestructura de Anthropic. Las declaras en tu array tools y no necesitas bucle de agente: Claude las llama por su cuenta y el resultado vuelve en la misma respuesta.

ToolQué hace
Web searchBusca en internet y devuelve resultados con citas
Code executionEscribe y ejecuta Python en un sandbox
Web fetchRecupera el contenido completo de URLs

En la respuesta aparecen tipos de bloque nuevos: server_tool_use para la llamada y un bloque de resultado para la salida, junto a los text de siempre.

Corren donde corre tu código, pero vienen en el SDK: no defines el schema.

ToolQué hace
MemoryClaude lee y escribe memoria entre sesiones
BashUn shell bash persistente para ejecutar comandos

Misma forma que una tool personalizada, pero el SDK te da el schema y un runner sensato.

search_response = client.messages.create(
    model="claude-opus-4-8",
    max_tokens=1024,
    tools=[{"type": "web_search_20260209", "name": "web_search"}],
    messages=[{"role": "user", "content": "What is Anthropic's latest model release? Answer in one sentence."}],
)

for block in search_response.content:
    if block.type == "server_tool_use":
        print(f"Tool call: {block.name} — {block.input}")
    elif block.type == "text":
        print(block.text)
⚠ El aviso del curso

Que algo esté validado en internet no significa que sea verdad. Comprueba siempre el trabajo de Claude.

Skills

Carpetas de instrucciones, scripts y recursos que Claude carga dinámicamente. En el núcleo, un fichero SKILL.md: subes una vez, adjuntas a cualquier llamada.

Las tools son sobre qué puede hacer Claude; las Skills, sobre cómo quieres que se haga.
◈ Carga progresiva

Al arrancar solo se cargan nombre y descripción. Cuando el agente decide que una Skill es relevante, entonces carga la Skill completa. Eso mantiene el contexto ligero aunque tengas muchas.

Subir y adjuntar

skill = client.beta.skills.create(
    display_title="Status Report Generator",
    files=files_from_dir("status-report-skill"),  # folder containing SKILL.md
)

print(skill.id)  # reference this ID in future requests
response = client.beta.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=4096,
    betas=["skills-2025-10-02", "code-execution-2025-08-25"],
    container={
        "skills": [
            {"type": "custom", "skill_id": skill.id, "version": "latest"}
        ]
    },
    tools=[{"type": "code_execution_20250825", "name": "code_execution"}],
    messages=[{"role": "user", "content": f"Generate the daily status report from this activity log:\n\n{activity_log}"}],
)
  • Es client.beta.messages.create y va con beta header: a fecha del vídeo, las Skills siguen en beta.
  • container.skills es una lista: puedes apilar varias Skills en una llamada.
  • Code execution encaja bien, porque los procedimientos de una Skill pueden hacer trabajo real.
ℹ El resultado en producción

El prompt del usuario es una línea; el procedimiento vive en la Skill. Así todos los PM reciben la misma estructura, tono y secciones sin copiar plantillas en prompts.

MCP

¿Por qué existe MCP si ya hay tools? Porque la pregunta real es quién mantiene el código de integración.

Con tools personalizadas escribes tres integraciones para Asana, Calendar y Slack — y luego las mantienes cada vez que esos servicios cambian su API. Con MCP, el proveedor publica y mantiene su servidor. Cuando su API cambia, tú no cambias nada.

¿Tool, skill o MCP?

¿Qué necesitas conectar o enseñar?

Conectar un servidor

response = client.beta.messages.create(
    model="claude-opus-4-8",
    max_tokens=1000,
    messages=[{"role": "user", "content": "What tools do you have available?"}],
    mcp_servers=[
        {
            "type": "url",
            "url": "https://mcp.linear.app/mcp",
            "name": "linear",
            "authorization_token": os.environ["LINEAR_MCP_TOKEN"],
        }
    ],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "linear"}],
    betas=["mcp-client-2025-11-20"],
)
  • mcp_servers declara la conexión: tipo, URL, nombre y token opcional.
  • Una tool de tipo mcp_toolset concede acceso. Por defecto, a todas las tools del servidor.
◈ Lo que no escribes

Ni un solo schema de tool. Claude introspecciona el servidor, recibe la lista de tools con sus schemas y elige la adecuada. El conector MCP está en beta.

Dejarlo en solo lectura

tools=[
    {
        "type": "mcp_toolset",
        "mcp_server_name": "slack",
        "default_config": {"enabled": False},
        "configs": {
            "search_messages": {"enabled": True},
            "list_channels": {"enabled": True},
        },
    }
]

Ahora Claude puede buscar y listar, pero no publicar ni borrar.

Gestión del contexto

Un millón de tokens suena a mucho, pero se acaba antes de lo que crees con un agente real. Y cuando la ventana se llena, la petición falla.

Qué cuenta como contexto

Todo lo que Claude ve en un turno: el system prompt, el historial de mensajes, las definiciones y resultados de tools, los ficheros y skills adjuntos y los bloques de thinking. Es la entrada de cada llamada: lo pagas al entrar y lo pagas al salir.

⚠ Pregunta 3 del quiz oficial

Importa porque la ventana es finita y pagas por lo que hay dentro — no porque Claude rechace peticiones de más de media ventana, ni porque los mensajes viejos se borren a los diez turnos, ni porque más contexto sea siempre mejor. El objetivo no es meterlo todo: es meter lo correcto.

Los cuatro patrones
response = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=1024,
    context_management={
        "edits": [
            {"type": "compact"}
        ]
    },
    messages=messages,
)
◈ Cómo se eligen

Cada patrón ataca un modo de fallo distinto: coste, tamaño de ventana, ausencia de estado. En producción normalmente se apilan los cuatro. O usas managed agents, que traen caching y compactación activados por defecto.

¿Qué son los agentes gestionados?

Un conjunto de APIs para construir y desplegar agentes a escala. Es el bucle de siempre — alojado en la infraestructura de Anthropic, en un contenedor aislado con sistema de ficheros, bash y búsqueda web.

Tres formas de usarlos

Arrastras un ticket a «in progress» y eso dispara una sesión. El backend la crea, apunta a un entorno con Lighthouse y Puppeteer preinstalados y monta tu repositorio de GitHub en el contenedor.

La rúbrica define qué es «hecho»: Lighthouse por encima de 90, sin recursos que bloqueen el render, todas las imágenes con lazy load. Un grader independiente evalúa, Claude lee el feedback, vuelve a entrar y arregla lo que se dejó — hasta 96 en la demo.

Cada llamada a tool vuelve al tablero en tiempo real por el event stream. Y puedes arrastrar un segundo ticket mientras el primero corre: dos sesiones, dos contenedores, en paralelo.

Un agente que sigue precios y cambios de plan de cada SaaS que paga la empresa, con el informe listo antes del stand-up. En cada ejecución busca en la web, corre un análisis de costes en Python en el sandbox, usa una skill de Excel, escribe un resumen y publica en Slack y crea la tarea en Asana vía MCP.

La clave está en la memoria: consulta qué encontró la semana pasada y guarda qué cambió. Así el informe puede decir «los costes de cómputo son un 15 % más bajos que la semana pasada» en vez de repetir precios estáticos.

Una tool personalizada de tu backend recibe la alerta y la mete en una sesión como tool result. Un coordinador delega en tres especialistas, cada uno en su propia ventana de contexto pero sobre el mismo sistema de ficheros, y sintetiza sus hallazgos.

Antes de que el resumen salga a Slack se dispara la política de permisos: lo ves, lo apruebas, y sale. Las acciones sensibles esperan a un humano. Y la memoria flagea el patrón: «esto se parece al problema de DNS de hace dos semanas».

Construir tu primer agente gestionado

Cuando el bucle va a correr minutos u horas, con estado que guardar y trabajo que reanudar tras un corte de red, no quieres ejecutarlo en tu servidor.

ℹ Sin acceso especial

Los managed agents están activados por defecto para toda cuenta de API.

Los cuatro primitivos, en orden

Los cinco pasos

agent = client.beta.agents.create(
    name="Line Counter",
    model="claude-opus-4-8",
    system="You are a helpful agent that completes small file tasks.",
    tools=[
        {"type": "agent_toolset_20260401", "default_config": {"enabled": True}}
    ],
)

environment = client.beta.environments.create(
    name="line-counter-env",
    config={"type": "cloud", "networking": {"type": "unrestricted"}},
)

session = client.beta.sessions.create(
    agent=agent.id,
    environment_id=environment.id,
    title="Count lines demo",
)
⚠ La trampa del capítulo

Abre el event stream antes de enviar el mensaje inicial. El stream solo entrega eventos que ocurren después de abrirse: si envías primero, te pierdes el arranque.

with client.beta.sessions.events.stream(session_id=session.id) as stream:
    # Stream is open — now send the kickoff
    client.beta.sessions.events.send(
        session_id=session.id,
        events=[
            {
                "type": "user.message",
                "content": [{"type": "text", "text": "Create a file in the temp directory, count its lines, and report back."}],
            }
        ],
    )

    for event in stream:
        if event.type == "agent.message":
            for block in event.content:
                if block.type == "text":
                    print(block.text, end="", flush=True)
        elif event.type == "agent.tool_use":
            print(f"\n[tool] {event.name}")
        elif event.type == "session.status_idle":
            print("\n--- Agent done ---")
            break
EventoQué es
agent.messageEl texto de Claude
agent.tool_useQué tool eligió
session.status_idleEl agente ha terminado

Fíjate en que es events, en plural: los eventos son cómo fluye todo en esta API.

◈ El cambio de mentalidad

No estás ejecutando un bucle while. Estás enviando eventos y leyendo eventos. Recurre a los managed agents cuando el bucle correría demasiado tiempo, haría demasiadas cosas o necesitaría sobrevivir a un percance; a un bucle manual, cuando quieras control total.

Construir con Claude Code

Escribir el código de la API a mano funciona. Que lo escriba Claude es más rápido.

La skill Claude API

Claude Code trae una skill integrada llamada Claude API. La invocas con /claude-api, o se carga sola cuando Claude Code detecta que usas el SDK de TypeScript.

⚠ Pregunta 5 del quiz oficial

El slash command es /claude-api. No /anthropic-api, no /claude-sdk, no /api-tools.

/plugin marketplace add AnthropicsSkills
⚠ La errata fácil

Fíjate en la s al final de Anthropics — se pasa por alto con facilidad.

Un prompt, código funcionando

Un buen prompt hace tres cosas:

Nombra el fichero que quieres cambiar.

Nombra el patrón que quieres que se use.

Nombra el estado final que esperas.

Claude Code rellena los stubs contra los tipos, añade una llamada al final del fichero, ejecuta el script y reporta la salida. Si algo falla, lee el error y parchea el código in situ. En la demo creó una tool con Zod, el tool runner y la función run.

◈ El patrón a recordar

Define una tool. Pásasela a un runner. Devuelve el resultado. No hace falta teclearlo de memoria: stub, delega, revisa el diff.
