FundamentosCapítulo 1

Acceder a Claude con el API

Una llamada al API es un modelo, un max_tokens y una lista de mensajes. Todo lo demás de este capítulo son matices sobre esos tres.

Los tres modelos

Interactivo · ¿cuál elijo?

La mayor inteligencia. Tareas complejas, multipaso, que exigen razonamiento profundo y planificación.

Contrapartida: mayor coste y latencia.
Elígelo cuando: la prioridad es la inteligencia.

Equilibrado: buena inteligencia, velocidad y coste. Fuerte en programación y edición precisa de código.

Elígelo cuando: tus requisitos son equilibrados. Es el de la mayoría de casos prácticos.

El más rápido, optimizado para velocidad y coste.

⚠ Lo que le falta

No tiene las capacidades de razonamiento de Opus/Sonnet. Ideal para interacción en tiempo real y procesamiento de alto volumen.

✓ El enfoque habitual

Usar varios modelos en la misma aplicación según lo que pida cada tarea, en vez de elegir uno solo para todo.

El flujo de acceso, en 5 pasos

El cliente envía el texto a tu servidor. ⚠ Nunca accedas al API directamente desde una aplicación cliente: la clave debe permanecer secreta.

Tu servidor llama al API con un SDK (Python, TypeScript, JavaScript, Go, Ruby) o HTTP plano. Obligatorios: clave + modelo + messages + max_tokens.

Generación en cuatro etapas: tokenización → embedding → contextualización → generación.

El modelo se detiene al alcanzar max_tokens o al generar un token especial de fin de secuencia.

El API devuelve el texto + contadores de uso + stop_reason.

Interactivo · las cuatro etapas de generación

Parte la entrada en tokens — palabras, trozos de palabra, símbolos, espacios.

Convierte los tokens en listas de números que representan todos los significados posibles de esa palabra.

Ajusta los embeddings según los tokens vecinos, para fijar el significado preciso.

La capa de salida produce probabilidades para la siguiente palabra. El modelo la selecciona combinando probabilidad y aleatoriedad, la añade y repite.

Aquí es donde entra temperature.

La primera petición

client.messages.create(
    model=model,
    max_tokens=1000,
    messages=[{"role": "user", "content": "What is quantum computing?"}]
)
⚠ max_tokens no es lo que crees

Es un límite de seguridad de longitud, no una longitud objetivo. No le pidas 1000 tokens esperando una respuesta de 1000 tokens.

El texto suelto se saca de message.content[0].text; la respuesta completa trae metadatos y estructura anidada.

Conseguir la clave: console.anthropic.com → Get API Keys → Create Key → workspace Default y un nombre → cópiala: se muestra una sola vez. Guárdala en un .env ignorado por git.

Conversaciones multi-turno

⚠ La limitación que lo condiciona todo

El API de Anthropic no almacena ningún mensaje. Cada petición es independiente y no recuerda nada de las anteriores.

La solución tiene dos partes: mantener la lista de mensajes a mano en tu código, y enviar el historial completo con cada petición de seguimiento. Necesitarás add_user_message, add_assistant_message y chat.

Los tres controles de la respuesta

Interactivo · qué controla cada uno
Controlan cómo responde Claude, no qué responde.

Se pasa como cadena al argumento system. La primera línea suele asignar el rol —"You are a patient math tutor"— seguida de instrucciones de comportamiento.

Implementación: diccionario params, añade la clave system solo si hay prompt, y desempaqueta con **. Si no hay, excluye el parámetro en vez de pasar None.

Parámetro de 0 a 1 que manipula directamente la distribución de probabilidad del siguiente token.

Cerca de 0

Determinista: siempre el token más probable.
Extracción de datos, tareas factuales.

Cerca de 1

Más probabilidad de tokens improbables: creativo e inesperado.
Brainstorming, escritura, marketing.

⚠ Matiz

Subir la temperatura no garantiza una salida distinta: solo aumenta la probabilidad de variación.

Pre-fill del mensaje de asistente

Añades a mano un mensaje de asistente al final. Claude lo ve como contenido que ya escribió él y continúa.

⚠ Continúa desde el final exacto

No desde frases completas. Tendrás que unir el pre-fill con la respuesta generada.

Stop sequences

Cortan la generación cuando aparece una cadena. El texto de la stop sequence no se incluye en la salida.

"cuenta del 1 al 10" + stop "five" → "one, two, three, four, ". Afinada a ", five" → "one, two, three, four".

◈ Datos estructurados: el patrón de tres piezas

Claude añade por su cuenta markdown, encabezados y comentarios al generar JSON o código. Para obtener el dato crudo:

  1. Mensaje de usuario — la petición.
  2. Pre-fill del asistente — el delimitador de apertura, ```json.
  3. Stop sequence — el delimitador de cierre, ```.

Claude asume que ya empezó a responder, genera solo el contenido y se detiene al llegar al cierre. Funciona con cualquier dato estructurado, no solo JSON.

Streaming

Mostrar la respuesta trozo a trozo mientras se genera. Resuelve que una respuesta puede tardar 10-30 segundos y los usuarios esperan feedback inmediato, no un spinner.

EventoQué es
message_startAcuse de recibo inicial
content_block_startEmpieza la generación
content_block_deltaContiene los trozos de texto reales — el que importa
content_block_stop / message_stopGeneración completa

client.messages.stream() con text_stream extrae solo el texto; get_final_message() ensambla todos los trozos para guardarlos.

MedirCapítulo 2

Evaluación de prompts

Pruebas automatizadas de prompts con métricas objetivas. El capítulo que separa retocar a ojo de mejorar de verdad.

Las tres salidas tras escribir un prompt

✗ Las dos trampas
  • Probarlo una o dos veces y desplegarlo
  • Probarlo con entradas propias y hacer ajustes menores para casos límite
✓ Lo recomendado
  • Pasarlo por un pipeline de evaluación para tener una puntuación objetiva
Los ingenieros infra-prueban los prompts de forma sistemática. Consigue puntuaciones objetivas antes de iterar y desplegar.

El workflow de 6 pasos

Prompt inicial. Un borrador de referencia que optimizar.

Dataset de evaluación. Pueden ser 3 ejemplos o miles, a mano o generados por LLM.

Variaciones. Interpola cada entrada en la plantilla del prompt.

Respuestas. Pasa cada variación por Claude y recoge las salidas.

Puntuar. Un grader puntúa cada respuesta y se promedia.

Iterar. Modifica según las puntuaciones, repite, compara versiones.

◈ El núcleo del pipeline

dataset + prompt + LLM + grader. Con muy poco código. No existe metodología estándar: hay herramientas de sobra, pero puedes empezar con una implementación propia.

Generar el dataset

A mano, o automatizado con Claude — usa modelos rápidos como Haiku para generarlo. Array de objetos JSON con una propiedad task.

El proceso reutiliza el patrón del capítulo 1: pre-fill con ```json, stop sequence ```, parsear y guardar.

Los tres tipos de grader

Interactivo · elige el grader

Comprobaciones programáticas: longitud, presencia de palabras, validación de sintaxis, índices de legibilidad. Rápidos y deterministas.

validate_json()    # → 10 si válido, 0 si error
validate_python()  # parseo del AST
validate_regex()   # compilación

Requiere que el dataset lleve una clave format con el tipo esperado.

◈ La fórmula final

puntuación = (puntuación_del_modelo + puntuación_de_sintaxis) / 2

Mide a la vez que sea correcto y que sea técnicamente válido.

Una llamada adicional al API que evalúa la salida original. Muy flexibles para calidad y seguimiento de instrucciones.

⚠ El error que arruina un model grader

Si le pides solo la puntuación, tiende a dar valores mediocres por defecto. Pídele fortalezas, debilidades, razonamiento y puntuación, en ese orden.

Formato JSON con pre-fill y stop sequences, parsea y promedia. Son flexibles pero pueden ser inconsistentes; aun así dan una referencia objetiva.

Una persona evalúa las respuestas. Los más flexibles, pero lentos y tediosos.

Requisitos comunes: devolver una señal objetiva, normalmente numérica, y definir los criterios por adelantado.

Prompt engineering

Cuatro técnicas. Lo que hace valioso este capítulo es que el curso mide cada una sobre el mismo caso: un plan de comidas para un atleta.

Interactivo · aplica las técnicas y mira subir la puntuación
ℹ El montaje del pipeline

Clase evaluadora flexible con concurrencia (ajusta max_concurrent_tasks a tus límites de rate) · prompt_input_spec define las entradas · extra_criteria añade requisitos al grading · output.html es el informe con resultados y puntuaciones.

Técnica 3 · Estructurar con XML

Envuelve las secciones en etiquetas descriptivas cuando interpolas contenido, para que el modelo distinga entre tipos de información.

✗ Sin estructura

Volcar código y documentación seguidos en el prompt.

✓ Con etiquetas

<my_code> y <docs> separados.

Nombra las etiquetas de forma específica: sales_records es mejor que data. Y funciona incluso con bloques cortos — envolver <athlete_information> aclara que es una entrada externa a considerar.

Técnica 4 · Dar ejemplos

One-shot = un ejemplo. Multi-shot = varios. Estructúralos con etiquetas XML que contengan entrada de muestra y salida ideal.

Dónde son más útiles

Casos límite (sarcasmo), formatos de salida complejos, y aclarar la calidad o el estilo esperados.

El bucle que cierra el curso

Usa como plantilla los ejemplos con mejor puntuación de tus evals. El capítulo 2 alimenta al 3.

  • Añade contexto para los casos límite: "be especially careful with sarcasm".
  • Incluye el razonamiento de por qué esa salida es la ideal — refuerza las características que buscas.
  • Colócalos después de las instrucciones y guidelines principales.

El proyecto: recordatorios con fecha

Tres problemas obligan a usar herramientas, y cada uno tiene la suya:

ProblemaHerramienta
Desconoce la hora — sabe la fecha, no la hora exactaFecha y hora actuales
Calcula mal el tiempo — se equivoca sumando fechasSumar duración

Las funciones de herramienta

def get_current_datetime(date_format="%Y%m%d %H:%M:%S"):
    if not date_format:
        raise ValueError("date format cannot be empty")
    return datetime.now().strftime(date_format)
◈ Los mensajes de error los lee Claude

Son visibles para él, así que puede reintentar con los parámetros corregidos. Escríbelos pensando en que los va a leer él: nombres descriptivos, validación de entradas, y errores con significado.

Los esquemas

JSON Schema es una especificación de validación de datos que no es específica de ML; la comunidad la adoptó para tool calling.

CampoContenido

description3-4 frases: qué hace, cuándo usarla, qué devuelve

✓ El truco para generarlos

Lleva tu función a claude.ai, pídele "write valid JSON schema spec for tool calling for this function, follow best practices in attached documentation" y adjunta la página de tool use de la documentación del API. Copia el resultado.

Envuelve el diccionario con ToolParam() de anthropic.types para evitar errores de tipo.

Los tres detalles que hay que memorizar

Interactivo · toca cada uno

Los mensajes pasan a contener varios bloques, no solo texto. La respuesta con herramienta trae un bloque de texto (explicación para el usuario) y un bloque tool use (nombre + argumentos).

⚠ El fallo

Al guardar en el historial, añade response.content entero, no solo el texto. Y actualiza add_user_message / add_assistant_message para soportar múltiples bloques.

Enlaza cada petición con su resultado cuando Claude hace varias llamadas simultáneas. Cada tool use tiene un ID único; cada resultado debe referenciar el suyo.

Campo del bloque de resultadoQué es
tool_use_idEl ID del bloque original
contentLa salida convertida a cadena, normalmente JSON
is_errorBooleano. Por defecto false
⚠ Dos cosas que se olvidan

El bloque de resultado va en un mensaje de USUARIO, no de asistente. Y hay que incluir los esquemas originales en el seguimiento, aunque no vayas a usar herramientas otra vez.

Campo que indica por qué dejó de generar Claude. stop_reason == "tool_use" significa que quiere llamar a una herramienta — es la condición del bucle.

Hay otros valores, pero este es el que se comprueba casi siempre.

El bucle multi-turno

No puedes predecir cuántas herramientas necesitará una consulta, así que el sistema debe manejar cadenas arbitrarias. Tres funciones:

run_conversation — llama a Claude, añade la respuesta al historial, comprueba stop_reason; si no es tool_use sale del bucle, si lo es llama a run_tools y añade los resultados como mensaje de usuario.

run_tools — filtra los bloques tool_use, ejecuta cada uno vía run_tool, y crea un tool_result por cada bloque.

run_tool — el dispatcher: empareja nombres con funciones. Escalable.

Añadir una herramienta nueva son tres pasos mecánicos: esquema + enrutado + implementación.

Dos trucos de diseño y tres herramientas que Claude ya trae.

Interactivo · las cinco

Permite ejecutar varias herramientas en paralelo dentro de un solo mensaje.

⚠ El problema que resuelve

Claude puede técnicamente enviar varios bloques tool_use en un mensaje, pero rara vez lo hace en la práctica. El resultado son llamadas secuenciales innecesarias.

El mecanismo: una herramienta que recibe una lista de invocations (nombre + argumentos). run_batch itera y llama a run_tool por cada una. Engaña a Claude para paralelizar dándole una abstracción de más alto nivel.

ExtenderCapítulo 6

RAG

Cómo extraer información concreta de un documento de 100-1000+ páginas sin chocar con los límites de contexto.

✗ Opción 1 · meter el documento entero
  • Choca con los límites de tokens
  • Pierde eficacia con prompts largos
  • Más caro y más lento
✓ Opción 2 · RAG
  • El modelo se centra en lo relevante
  • Escala a documentos grandes y múltiples
  • Prompts pequeños, menos coste, más rápido
RAG cambia simplicidad por escalabilidad y eficiencia. El reto está en definir qué es "relevante" y cuál es la estrategia de troceado.

Troceado

⚠ Por qué importa tanto

La calidad del troceado impacta directamente en el rendimiento. El ejemplo del curso: texto médico sobre un "bug" recuperado para una consulta de ingeniería de software sobre bugs.

Interactivo · las tres estrategias

Dividir en cadenas de igual longitud. Fácil de implementar y la más común en producción.

✗ Corta palabras a la mitad y pierde contexto.

Solución: solapamiento — incluir caracteres de los trozos vecinos. Duplica texto, pero mejora el significado de cada trozo.

Dividir según encabezados, párrafos o secciones. Mejor para markdown y HTML.

✗ Requiere que el formato esté garantizado. Ejemplo: partir por ## para crear trozos por sección.

Usar NLP para agrupar frases y secciones relacionadas por similitud semántica. La técnica más avanzada, y la de implementación más compleja.

GranularidadCuándo
Por carácterEl recurso más fiable: funciona con cualquier documento
Por fraseBuen término medio, si la detección funciona bien
Por secciónResultados óptimos, pero exige entrada estructurada

No hay un método universalmente mejor. Depende de qué garantías tengas sobre el documento.

Embeddings

Representación numérica del significado. El modelo recibe texto y devuelve una lista larga de números en rango -1 a +1.

ℹ El matiz honesto

Cada número puntúa cualidades desconocidas. En teoría cada uno mide un aspecto —alegría, relevancia temática— pero su significado real es desconocido para quien los usa.

Permiten emparejar por similitud semántica en vez de por palabras clave. Anthropic recomienda Voyage AI; cuenta aparte, gratis para empezar.

El flujo completo

Preprocesado (1-4)

Trocear → generar embeddings → normalizar (lo hacen las APIs solas) → guardar en base vectorial.

Tiempo real (5-7)

Embedding de la consulta con el mismo modelo → búsqueda por similitud → ensamblar el prompt.

MétricaRangoInterpretación
Similitud coseno-1 a 1Más cerca de 1 = más similar
Distancia coseno1 − similitudMás cerca de 0 = más similar
⚠ Al implementarlo

Guarda el texto original junto al embedding — store.add_vector(embedding, {content: chunk}). Sin los metadatos con el contenido, los resultados de la búsqueda no sirven de nada.

Las cuatro mejoras sucesivas

Interactivo · cada una arregla un fallo de la anterior

El fallo que arregla: la búsqueda semántica sola puede pasar por alto coincidencias exactas, devolviendo resultados irrelevantes aunque un término específico aparezca mucho.

BM25 (Best Match 25) es búsqueda léxica: tokeniza la consulta, cuenta la frecuencia de cada término en todo el corpus, asigna importancia relativa y rankea.

◈ La idea

Los términos raros pesan más que los comunes. Un término que aparece en todo el corpus es menos relevante que uno específico.

El fallo que arregla: tener dos índices no sirve si no sabes fusionar sus resultados.

El Retriever reenvía la consulta a ambos índices y los fusiona con Reciprocal Rank Fusion:

RRF_score = Σ 1 / (rank + 1)    por cada método

Ejemplo: vectorial da [doc2, doc7, doc6], BM25 da [doc6, doc2, doc7]. Tras RRF: [doc2, doc6, doc7] — porque doc2 salió alto en ambos.

El fallo que arregla: la recuperación inicial se pierde matices de la intención.

Un LLM reordena los resultados por relevancia después de recuperarlos. Usa IDs de documento, no el texto completo, por eficiencia. Pre-fill + stop sequence para salida JSON estructurada.

Contrapartida: sube la precisión, añade latencia por la llamada extra.

✓ El ejemplo

La consulta "¿qué hizo el equipo de ingeniería con el incidente de 2023?" priorizó correctamente la sección de ingeniería de software sobre la de ciberseguridad tras el reranking. El matiz era "ENG team" vs "engineering team".

El fallo que arregla: al partir el documento, cada trozo pierde el contexto del original.

Antes de generar el embedding: envías el trozo + el documento fuente a Claude, que genera un contexto de situación breve; lo unes al trozo original = trozo contextualizado, y ese es el que indexas.

ℹ Si el documento no cabe en un prompt

Contexto selectivo: los trozos iniciales (1-3) para el resumen + los inmediatamente anteriores al objetivo para contexto local, saltándose los del medio.

Funcionalidades de Claude

Cinco capacidades que vienen dadas y no hay que construir.

Interactivo · las cinco

Permite a Claude razonar antes de generar la respuesta final, mostrando un proceso de pensamiento separado y visible.

⚠ Los dos números

Thinking budget mínimo: 1024 tokens.
max_tokens debe superarlo — con budget 1024, max_tokens ≥ 1025.

Cuándo activarlo: cuando optimizar el prompt no haya conseguido la precisión que buscas. Usa evals para decidirlo.

Coste: se cobran los tokens de pensamiento y añade latencia. El bloque de pensamiento lleva una firma criptográfica que impide manipularlo. Los bloques redactados son pensamiento cifrado que los sistemas de seguridad marcaron; se entregan igual para mantener la continuidad.

Analizar, comparar, contar y describir imágenes dentro de mensajes de usuario.

Límites: máximo 100 imágenes por petición, restricciones de tamaño, y consumen tokens calculados según alto y ancho en píxeles.

⚠ El factor crítico

La precisión depende enteramente de lo sofisticado que sea el prompt, no de la calidad de la imagen. Los prompts simples fallan a menudo.

Técnicas: instrucciones paso a paso, ejemplos multi-shot alternando pares de imagen y texto, guidelines claras y pasos de verificación.

Claude lee PDF directamente, con código casi idéntico al de imágenes.

Extrae texto + imágenes + gráficas + tablas y contenido mixto. Solución integral para análisis documental.

Para qué sirve de verdad: transparencia. El usuario puede verificar las fuentes en vez de que parezca que Claude habla de memoria.

Files API: subes ficheros por adelantado y los referencias después por ID, en vez de incluir los datos crudos en cada petición.

Code execution: Claude ejecuta Python en contenedores Docker aislados. No hace falta implementación, solo incluir el esquema predefinido.

⚠ La restricción que lo une todo

Los contenedores no tienen acceso a red. La entrada y salida de datos depende de la Files API. Por eso las dos cosas van en la misma lección.

Claude también puede generar ficheros dentro del contenedor —gráficas, informes— que se descargan con los IDs devueltos.

OptimizarCapítulo 8

Prompt caching

Acelera las respuestas y reduce el coste reutilizando el trabajo computacional de peticiones anteriores.

El problema
Petición 1

Claude procesa la entrada, genera, y descarta todo el trabajo

⇠trabajo tirado
Petición 2 · entrada idéntica

Tiene que repetir todo el trabajo que acaba de tirar

El caché almacena el resultado de procesar la entrada en vez de descartarlo. Cuando la misma entrada vuelve a aparecer, Claude recupera el trabajo cacheado en lugar de reprocesar.

Las reglas

ReglaValor
Duración1 hora máximo
ActivaciónManual — hay que añadir un cache breakpoint
AlcanceTodo el contenido hasta el breakpoint, incluido
InvalidaciónCualquier cambio antes del breakpoint invalida el caché entero
Orden de procesadotools → system prompt → messages
Máximo de breakpoints4 por petición
Umbral mínimo1024 tokens para que se cachee
⚠ El fallo más fácil de cometer
# Forma corta — NO admite cache control
content = "una cadena de texto"

# Forma larga — OBLIGATORIA para cachear
content = [{"type": "text", "text": "contenido", "cache_control": {...}}]

En la práctica

Cachear esquemas de herramienta

Añade cache_control de tipo "ephemeral" a la última herramienta. Clona la lista antes para no modificar los esquemas originales.

Cachear el system prompt

Envuélvelo en un diccionario de bloque de texto con cache_control de tipo "ephemeral".

Campo de usoQué mide
cache_creation_input_tokensTokens escritos al caché en el primer uso
cache_read_input_tokensTokens recuperados en peticiones idénticas posteriores

Varios breakpoints crean varias capas: son posibles los aciertos parciales si solo cambia el contenido posterior.

ℹ Si no ves aciertos

Si estás iterando sobre el system prompt, cada cambio invalida el caché y fuerza una creación nueva. Es esperable.

MCP

Capa de comunicación que aporta a Claude contexto y herramientas sin obligarte a escribir código tedioso.

◈ El valor central

Traslada la carga de integración del desarrollador de la aplicación al mantenedor del servidor MCP. Un chatbot de GitHub exigiría implementar herramientas para repositorios, PRs, issues y proyectos. Con MCP, eso lo mantiene otro.

Los tres componentes de un servidor

Interactivo · tools, resources y prompts

El decorador @mcp.tool auto-genera el JSON Schema a partir de la firma de la función Python. Usa Field() de pydantic para describir cada argumento.

✓ Compara con el capítulo 4

Allí escribías el esquema a mano o se lo pedías a claude.ai. Aquí el SDK lo genera solo. Esa es la diferencia práctica de MCP.

Mecanismo para que el servidor exponga datos al cliente para operaciones de lectura. Decorador @mcp.resource con URI y MIME type.

TipoURI

Con plantilladocs://documents/{doc_id} — el SDK parsea los parámetros solo
◈ Resources vs. tools

Resources = datos, proactivos — traer el contenido cuando se menciona con @.
Tools = acciones, reactivas — cuando Claude decide llamarlas.

Plantillas de prompt predefinidas y ya probadas que el servidor expone al cliente.

En vez de que el usuario escriba prompts improvisados, el autor del servidor crea prompts de calidad, ya evaluados, adaptados a su dominio.

El decorador @mcpserver.prompt envuelve una función que devuelve una lista de mensajes lista para Claude. En el cliente aparecen como slash commands con autocompletado, piden los parámetros y ejecutan el flujo.

El flujo cliente-servidor

El usuario consulta a tu servidor.

Tu servidor pide la lista de herramientas al cliente MCP, que manda list tools request al servidor MCP.

Tu servidor envía la consulta + las herramientas a Claude.

Claude pide ejecutar una herramienta; el cliente MCP manda call tool request.

El servidor MCP ejecuta — p. ej. llama al API de GitHub — y el resultado vuelve por toda la cadena hasta el usuario.

Agnóstico del transporte: stdio, HTTP o WebSockets. El montaje habitual es cliente y servidor en la misma máquina, por entrada/salida estándar.

✓ El inspector

mcp dev servidor.py abre un depurador en el navegador para probar el servidor sin conectarlo a ninguna aplicación: conectar → tools → seleccionar → introducir parámetros → run tool.

Claude Code y computer use

Las dos aplicaciones desplegadas de Anthropic. Están aquí porque ejemplifican cómo funcionan los agentes, justo antes del capítulo de arquitectura.

Claude Code no es un generador de código: es un ingeniero colaborador en el proyecto.

Arranque

Instala Node.js (compruébalo con npm help), luego npm install, y ejecuta claude para iniciar sesión.

Abre el proyecto y pídele que lea el README y ejecute las instrucciones de montaje.

Ejecuta init → escanea el codebase buscando arquitectura y estilo, y crea claude.md, que se incluye automáticamente como contexto después.

Memorias: de proyecto (compartida), local y de usuario. Usa # para añadir notas concretas; puedes editar claude.md a mano o relanzar init.

Las dos estrategias de prompting

Método 1 · Tres pasos

① Identifica los ficheros relevantes y pide análisis. ② Describe la funcionalidad y pide que planifique, sin código todavía. ③ Pide implementar el plan.

Método 2 · Guiado por tests

① Aporta contexto. ② Pide que sugiera tests. ③ Selecciona e implementa. ④ Pide código hasta que los tests pasen.

◈ El principio

Claude Code es un multiplicador de esfuerzo. Instrucciones más detalladas = resultados significativamente mejores.

Ampliar, paralelizar, automatizar

Interactivo · tres formas de escalarlo

Claude Code lleva un cliente MCP embebido.

claude mcp add [nombre-servidor] [comando-de-arranque]

Los servidores añaden funciones en tiempo real, sin tocar el núcleo. Casos habituales: Sentry, Jira, Slack, herramientas propias del flujo.

El problema: varias instancias modificando los mismos ficheros generan conflictos y código inválido.

La solución: git work trees — copias completas del proyecto en directorios separados, cada una en su rama.

Automatízalo con comandos propios en .claude/commands/*.md, usando el marcador $ARGUMENTS.

✓ El resultado

Un solo desarrollador comandando un equipo virtual de ingenieros. Claude resuelve los conflictos de merge y limpia el work tree al terminar.

Una GitHub Action diaria revisa producción, recupera los logs de CloudWatch de 24 h, Claude identifica y deduplica errores, genera correcciones y abre un pull request.

Lo que aporta: captura errores que solo pasan en producción — típicamente configuración entre entornos: IDs de modelo inválidos, claves de API que funcionan en local y fallan desplegadas.

Computer use por dentro

Claude toma capturas, hace clic, escribe y navega interfaces, siguiendo instrucciones multipaso de forma autónoma. Corre en un contenedor Docker aislado.

◈ Es exactamente el flujo de tool use del capítulo 4

Se envía un esquema especial que se expande por detrás, con acciones como mover ratón, clic izquierdo o captura. Claude envía la petición de tool use y el desarrollador debe cumplirla mediante el contenedor.

⚠ Lo que hay que tener claro

Claude no manipula directamente ningún ordenador. Computer use = el sistema de herramientas + un entorno de computación que aportas tú. Anthropic da una implementación de referencia en Docker con el código de ratón y teclado ya hecho.

Agentes y workflows

Dos estrategias para tareas que Claude no puede completar en una sola petición. Y el consejo final del curso, que va a contracorriente.

◈ La regla de decisión

Workflow cuando entiendas la tarea con precisión y sepas la secuencia exacta de pasos. Agente cuando los detalles no estén claros.

⚠ Ojo

Los patrones son formas de implementación que han funcionado a otros. Identificar el patrón no lo implementa por ti — sigues teniendo que escribir el código.

Partir una tarea compleja en subtareas simultáneas y agregar resultados.

✗ En vez de

Un prompt grande pidiendo elegir entre metal, polímero, cerámica y compuesto con todos los criterios a la vez.

✓ Haz

Peticiones paralelas, cada una evaluando un material, más un paso de agregación que compare.

Beneficios: foco (cada subtarea hace un análisis), modularidad (cada prompt se mejora por separado), escalabilidad (añadir subtareas no afecta a las existentes) y calidad.

Partir la tarea en pasos secuenciales distintos en vez de un prompt complejo único.

◈ El caso de uso menos obvio, y el más útil

Cuando Claude ignora sistemáticamente restricciones en prompts largos por mucho que las repitas — no menciones la IA, sin emojis, tono profesional— y viola algunas pase lo que pase.

Solución: ① envía el prompt y acepta la salida imperfecta; ② pide una reescritura señalando las violaciones concretas. Un workflow que parece trivial se vuelve imprescindible.

Diseñar un agente

◈ El principio de abstracción de herramientas

Da herramientas genéricas y abstractas, no hiperespecializadas.

✓ Abstractas
  • bash
  • web_fetch
  • file_write

Es lo que usa Claude Code.

✗ Especializadas
  • refactor_tool
  • install_dependencies

Limitan las combinaciones posibles.

Funciona mejor con un conjunto pequeño de herramientas flexibles que se pueden combinar de formas inesperadas.

Inspección del entorno

Tras cada acción, el agente necesita feedback más allá del valor que devuelve la herramienta, para entender el nuevo estado.

Computer use

Captura después de cada acción, porque no puede predecir el resultado exacto de pulsar un botón.

Edición de código

Leer el fichero antes de modificarlo, para conocer el estado existente.

Permite al agente medir su progreso, detectar errores y adaptarse en vez de operar a ciegas.
